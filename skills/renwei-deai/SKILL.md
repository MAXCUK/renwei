# 人味 · 去 AI 味

把中文小说正文改得像人写的：先量化，再改写，再复检。

## 边界

- **只改表达，不改事实。** 人名、地名、数字、事件顺序、伏笔、台词里的信息都不动。需要补细节时，从上下文和设定里找；找不到就问用户，不要编一个新设定塞进去。
- **看频率，不一刀切。** 一章出现一次“深吸一口气”没关系，五次才是问题。脚本按每万字限额判断，限额内的命中不用改。
- **尊重作者有意的写法。** 在小说工作区里时，先读 `设定/文风.md` 的“例外”一节，例外里允许的写法不改。
- **别矫枉过正。** 不要把比喻、四字词、破折号删光，也不要把每句都改短，那是另一种机械腔。

## 流程

### 1. 检测

脚本路径相对本 skill 所在目录：

```bash
node scripts/deai-check.mjs <文件或目录>
```

用户只贴了文字时，先存成临时文件再跑，或者用 `-` 从标准输入读。常用选项：

- `--genre 古风`：题材。古风、热血会放宽成语、比喻、“道”的限额；都市、悬疑按默认标准。
- `--extra 我的禁用词.txt`：叠加自定义禁用词。在工作区里会自动读 `设定/禁用词.txt` 和 `设定/去AI味.json`。
- `--json`：输出 JSON，方便你逐条处理。
- `--all`：每条规则列出全部命中（默认最多 5 处）。

读报告：**AI 腔指数**是每千字的加权超额命中数（高 3 分、中 2 分、低 1 分）。1 以下算自然，1–3 有些 AI 腔，3–6 明显，6 以上严重。【高】级命中一律要改；【中】【低】只改超出限额的部分；【节奏】说的是整体句长和段落结构。

### 2. 读改法

这时才读 `references/patterns.md`，里面有每类 AI 腔的成因、改法和前后对照。写正文时不要加载这份清单：清单里列出的套话会被反复想起，越禁越多。

### 3. 三遍改写

**第一遍，去套话。** 处理所有【高】级命中和超额的【中】级命中。换成具体的动作、物件和细节，或者直接删掉。把“嘴角勾起一抹弧度”换成“嘴角上扬”不算改，只是换了个同义套话。

**第二遍，去书面腔。** 台词改口语；删掉解释动作含义的句子；拆开整齐的排比和对仗；调整句子长短，让节奏有起伏。

**第三遍，回人味。** 每个场景补一个只属于这个场景的细节；让视角人物的处境和偏见渗进叙述用词；允许一点毛边：话说一半、念头跑偏、动作没做完。

### 4. 复检

再跑一次脚本。【高】级命中应该是 0，指数应该明显下降。如果指数不降反升，多半是改写时引入了新套话，回头看新增的命中。

### 5. 交付

- 输出改后全文，再附不超过 10 行的修改说明：改了哪几类，各举一处“原句 / 改句”。
- 在工作区里时：改后正文写回 `正文/`，检测结果和修改说明写进 `审稿/第NNN章.md` 的“去 AI 味”一节。
- 用户反复把某种写法改回去，说明那是他的风格。建议把对应规则加进 `设定/去AI味.json` 的 `allow`，或者交给 renwei-style 记进文风例外。

## 只诊断，不改写

跑脚本，按严重程度挑出最该改的 3 类问题。每类引一处原文，给一种改法示范，不改全文。

## 自定义

- 个人禁用词：工作区的 `设定/禁用词.txt`，每行一个短语；写成 `/正则/` 按正则匹配；行尾加 `@2` 表示每万字允许 2 次。
- 关掉或放宽规则、设定题材：工作区的 `设定/去AI味.json`。
- 改内置规则库：`data/rules.json`，每条规则都带“应命中/不应命中”的例句。
- 详细格式见 `references/custom-rules.md`；`node scripts/deai-check.mjs --list-rules` 列出全部规则。

## 文件

- `scripts/deai-check.mjs`：检测脚本，Node.js 18.3 以上，不需要安装依赖。
- `data/rules.json`：规则库和节奏检查的阈值。
- `references/patterns.md`：每类 AI 腔的成因、改法和前后对照（改稿时读）。
- `references/custom-rules.md`：禁用词表、工作区配置、规则字段说明。
