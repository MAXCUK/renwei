# 接手旧稿、续写、卡文

## 接手旧稿

用户已经写了一部分（或者从别处拿来一部稿子），要接着写。

1. **建工作区**（如果还没有），把旧稿按章存进 `正文/`，文件名用 `第001章.md` 这种格式。
2. **取文风基线。** 用最近的 3–5 章交给 renwei-style：
   ```bash
   node <renwei-style>/scripts/style-fingerprint.mjs 正文/第010章.md 正文/第011章.md 正文/第012章.md --save 设定/文风指纹.json
   ```
   再按它的“样本建档”流程写 `设定/文风.md`。
3. **反向提取。** 从旧稿里整理出人物卡、世界规则、伏笔（已经埋下还没收的，状态写“已埋”）、时间线、每章摘要和人物状态。每一条都标出处章节。
4. **列不可改动清单。** 把你认为不能动的设定列出来，让用户逐条标“锁定 / 可以调整 / 删除”。锁定的写进 `设定/不可改动.md`。用户确认之前，不写新章。
5. **先写一章样章。** 给用户看，确认风格接得上、人物没走样，再正常往下写。

## 续写

用户说“接着写”时：

1. 跑 `novel-status.mjs`，读 `进度.md`，确认下一章是第几章、有没有细纲。
2. 没有细纲就先写细纲给用户看（讨论模式），或者直接按大纲写细纲再写正文（快速模式）。
3. 按主流程的“写一章的标准循环”走。

## 卡文

先诊断卡在哪，再给路线。

| 卡点 | 表现 | 办法 |
| --- | --- | --- |
| 动机不够 | 主角没有非做不可的理由，剧情靠作者推 | 加压：给一个时间限制，让他失去某样东西，或者让某个人逼他 |
| 冲突用完 | 上一个对手解决了，下一个目标模糊 | 让上一次胜利带来新的麻烦：赢来的东西有人要抢，或者赢的方式留了把柄 |
| 前提没铺 | 想写的高潮缺前提，写出来不成立 | 回头补一两章铺垫，或者把高潮往后推 |
| 节奏疲劳 | 连续几章同一种功能，作者自己都写烦了 | 插一章喘息，换一个视角人物，或者跳一段时间 |
| 不知道终点 | 写着写着没了方向 | 先定结局方向，再倒推三个必经节点 |

诊断完给三条路线，让用户选：

- **稳妥：** 顺着现有线索往下走，风险小。
- **提速：** 跳过铺垫，直接上冲突，节奏快但要补逻辑。
- **意外：** 引入一个合理、但读者没想到的变量。

每条路线写清楚：接下来三章大概写什么，要改动哪些设定，会影响哪些伏笔。

## 风格漂移

写了十几章以后味道变了：

1. 用 renwei-style 的漂移检查，对比最近几章和 `设定/文风指纹.json`。
2. 3 项及以上偏离：挑偏离最大的两项，具体说明怎么回拉，例如“对话占比掉到 12%，下一章至少一半场景用对话推进”。
3. 偏离是剧情需要（打斗章、回忆章）就不用拉回来，在 `进度.md` 里记一笔。
